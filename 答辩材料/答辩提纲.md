# 答辩材料框架（2026 openvela AI 硬件开发者大赛）

> 用途：比赛答辩/作品展示的准备提纲。按"评委想知道什么"组织。
> 时间预算：5 分钟演示 + 3 分钟问答。

---

## 一、开场 30 秒（一句话定位）

> "我们做了一台**面向听障群体的端侧手语翻译终端**：
> 摄像头拍手语手势 → 板载 AI 识别 → 屏幕显示 + 语音播报，
> 全程端侧推理、无云端依赖，帮听障人士完成日常简易沟通。"

## 二、痛点与意义（为什么做）

- 中国听障群体约 **2700 万**，手语沟通门槛高
- 现有翻译依赖 App（要网络、要专用设备）、成本高
- 本项目：**低成本端侧设备**（约几百元硬件），离线可用，隐私安全

## 三、技术方案（怎么做的）

```
硬件: ESP32-P4-Function-EV-Board（400MHz 双核 RISC-V + AI 指令扩展）
系统: OpenVela（NuttX 系 RTOS，官方不支持 P4，本项目自行移植）

应用层: LVGL 界面 + TFLite Micro 推理 + I2S 语音 + HTTP 上传
系统层: OpenVela（视频/音频/网络/图形栈）
BSP层: 自行移植（芯片层 + 板级层 + HAL 适配 10+ 处修复）
```

## 四、核心亮点（评委记忆点，讲透 1-2 个）

| # | 亮点 | 讲法 |
|---|------|------|
| 1 | **BSP 移植**（最硬） | OpenVela 官方不支持 ESP32-P4，我们完成芯片层/板级层/HAL 全套移植，固件编译成功。展示：报错→修复的真实截图（答辩加分项） |

## 六、常见问题与回答要点（评委可能问）

| 问题 | 回答要点 |
|------|---------|
| 为什么不用云端 API 识别？ | 比赛要求端侧 + 听障场景需离线/隐私；云端延迟和网络依赖不可接受 |
| "NPU"和向量扩展是什么关系？ | P4 无独立 NPU，靠 400MHz 双核 RISC-V 的 AI 指令扩展 + HiFi4 DSP，12 类轻量 CNN 足够 |
| 移植最大的难点？ | HAL（乐鑫驱动库）与 OpenVela（NuttX）两套体系的 API 差异：头文件迁移、函数改名、中断映射——10+ 处修复，全部有据可查 |
| 准确率多少？怎么保证？ | 目标 ≥90%（12 类）；INT8 量化 + 数据增强；真机补采微调 |
| 为什么选 OpenVela 不选 ESP-IDF？ | 比赛要求 + OpenVela 提供完整图形/网络/音频栈，便于做应用 |
| 数据从哪来？ | 自行采集（多背景多人员）+ 数据增强；12 类每类 ≥150 张 |
